综合理解

Agent、上下文与 Skill

三个概念分别回答：谁来行动、行动时看什么、应该怎样做。

核心关系

Skill
提供方法与规则
→
上下文
装载当前所需信息
→
Agent
据此规划并执行

Skill 的相关内容会被选择性地放入上下文；Agent 读取上下文后决定是否调用工具、如何处理结果，并在循环中继续行动。三者不是同一层级的同义词。

用一个研究任务串起来

1. Skill 提供方法

规定如何拆题、怎样判断来源可信、报告必须包含哪些部分。

2. 上下文提供材料

包含用户问题、历史进展、检索到的网页片段、时间和输出格式。

3. Agent 执行决策

决定先搜索还是先整理，调用工具并根据反馈修正计划。

分层对照

问题答案典型内容
谁负责推进任务？Agent规划、工具调用、重试、停止
模型此刻看到了什么？上下文指令、历史、资料、工具结果
应该采用什么流程？Skill领域规则、步骤、模板、验收标准

为什么要分开

  • 可维护：流程变化时更新 Skill，不必重新训练模型。
  • 可控：上下文只提供完成当前任务所需的最小信息。
  • 可复用：同一个 Skill 可以服务多个 Agent 或工作流。
  • 可评估：分别测量流程遵循、信息利用和任务完成率。
不要把所有内容都塞进 Skill，也不要让 Agent 自由访问所有工具。清晰的边界通常比更长的提示词更可靠。

常见误解

“Skill 就是工具”

工具执行动作，Skill 描述何时以及如何使用动作。

“上下文就是记忆”

上下文是当前输入集合；记忆是可能被再次检索的长期信息。

“Agent 一定完全自主”

生产系统常在高风险节点设置审批、权限和停止条件。

最终心智模型

可以把它们想成一个工作团队：Skill 是作业手册，上下文是桌面上的材料，Agent 是负责推进工作的执行者。模型是执行者的推理能力，工具则是它可以使用的设备。
