概念一

Agent

能够围绕目标感知信息、规划步骤、调用工具并根据结果持续行动的软件系统。

一句话理解

普通聊天模型主要回答一次问题；Agent 则把模型放进一个可执行的循环：目标 → 观察 → 思考/规划 → 行动 → 反馈，直到完成任务或安全停止。

Agent 不是“更聪明的聊天框”，而是模型、工具、状态和控制逻辑的组合。

组成部分

模型

负责理解指令、判断下一步并生成工具调用或文本。

工具

搜索、数据库、代码执行、浏览器、文件系统等外部能力。

状态

当前任务、历史消息、工具结果、长期记忆和权限上下文。

控制器

编排循环、重试、超时、审批、错误处理和停止条件。

基本工作流

while not finished:
    context = collect(goal, history, available_tools)
    decision = model.plan(context)
    if decision.requires_approval:
        ask_human(decision)
    result = execute(decision.tool, decision.arguments)
    history.append(result)
return final_answer

真实系统通常还需要参数校验、权限隔离、幂等操作、预算限制和可观测日志。

与相关概念的区别

系统特点是否自主行动
聊天机器人输入问题，输出回答通常否
工作流步骤预先固定有限
Agent根据目标和环境动态选择下一步是
多 Agent多个角色协作、分工或互相审查是

示例：资料研究 Agent

  1. 解析用户问题，拆成若干子问题。
  2. 调用搜索工具，读取可信来源。
  3. 去重、比较日期和出处，标记不确定结论。
  4. 整理证据，生成带引用的报告。
  5. 若来源冲突或需要付费权限，暂停并请求人工决定。

优势与风险

优势

  • 可执行多步骤任务
  • 能连接真实数据与软件
  • 可根据反馈修正计划
  • 适合重复性流程自动化

风险

  • 工具调用错误或参数失控
  • 提示注入和数据泄露
  • 循环过长导致成本失控
  • 错误结果被包装得很可信

设计检查清单

  • 为每个工具定义严格的输入 schema 和最小权限。
  • 对删除、付款、发送消息等副作用操作增加人工确认。
  • 设置最大步数、超时、预算和失败回退。
  • 记录模型决策、工具输入输出和最终结果，便于审计。
  • 使用真实任务集评估成功率、成本、延迟和安全性。
